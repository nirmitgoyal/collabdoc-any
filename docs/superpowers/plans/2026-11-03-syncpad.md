# Syncpad character-level editor implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Two users can independently edit plain text, exchange edits in any order, and continue editing the same converged document.

**Architecture:** A replica translates visible indexes into stable character IDs when a user edits. Local and remote operations use one merge path. A deterministic traversal translates the merged history back into visible text.

**Tech Stack:** Python 3.10+, frozen dataclasses, standard-library unittest. The repository has no existing application stack. Run all commands from its root.

**Spec:** [Syncpad character-level editor](../specs/2026-11-03-syncpad-design.md)

## Global Constraints

- Each replica starts empty with the same invisible root. Share initial text by replaying identical seed operations.
- Each replica has a distinct immutable ASCII actor ID. Assume a single writer per actor and serialized calls within a replica.
- Indexes count Unicode scalars. Reject invalid indexes and invalid local character input without changing state.
- Remote input is trusted, well-formed output from these APIs for this document. Eventual delivery of all dependencies is assumed for the final result.
- Visit siblings by descending counter, then ascending actor ID in ASCII order. Deleted anchors are retained for the document lifetime.
- Implement reconciliation directly. UI, real transport, persistence, restart-safe actor identity, tombstone collection, deployment, Docker and CI are outside this exercise.

## Review Focus

- A delayed high-counter operation advances the clock immediately, even while unreachable (Task 2).
- A failed local edit consumes no ID and leaves subsequent edits correctly positioned (Task 2).
- A combining mark occupies its own position, while a surrogate is invalid input (Task 2).
- Replaying a deletion after inserting a descendant keeps the descendant visible (Task 1).
- Replicas that reach the same display through different schedules must still be able to exchange a subsequent edit (Task 3).

```python

r.insert(1, "\u0301")
r.insert(0, "😀")
self.assertEqual(r.text(), "😀e\u0301")
for index, expected in [(0, "e\u0301"), (1, "e"), (0, "")]:
    r.delete(index)
    self.assertEqual(r.text(), expected)

r.receive(Insert(OpId(12, "bob"), OpId(11, "bob"), "z"))
for index in (-1, 1):
    with self.assertRaises(IndexError): r.insert(index, "x")
for index in (-1, 0):
    with self.assertRaises(IndexError): r.delete(index)
for character in ("", "ab", "e\u0301", "\ud800"):
    with self.assertRaises(ValueError): r.insert(0, character)
self.assertEqual(r.text(), "")
x = r.insert(0, "x")
self.assertEqual(x, Insert(OpId(13, "alice"), None, "x"))
self.assertEqual(r.delete(0), Delete(OpId(14, "alice"), x.id))
```
